# Desktop integration review — ANS-76 / L11 and F08 implications (2026-11-19)

**Scope:** `crates/ui-gpui/src/{lib,daily,smoke}.rs`, `crates/ui-gpui/Cargo.toml`, the workspace
`Cargo.toml` entries they rely on, and the read paths that determine whether the desktop's
claims are true (`crates/alpha/src/{daily_driver,catalog}.rs`, `crates/onboarding/src/*`,
`apps/cli/src/main.rs`, `crates/core/src/refresh.rs`, `crates/storage/src/settings.rs`).
F08 was assessed from the UI semantics and the framework gate, not from a screen-reader run.

**Kaneo tickets:** ANS-76 `m3up892wzzmw0hgcvmo6scoi` (L11) and F08
`g5msriuv411w58vws5sxwkh3`.

**Reviewer:** independent subagent. No implementation or test file was edited. The only
repository file written is this review.

**Environment:** Windows 10.0.26200, Rust 1.99.1, Cargo 1.99.1, PowerShell 7.7.0.
Test, check, clippy and run commands were executed with `--offline`; `cargo fmt` does not
accept `--offline` and was run locally without network access.

> **Working-tree note:** `crates/storage` was being edited by another process during this
> review. Two intermediate reruns failed in `crates/storage` (`lock::owner_path_for` and a
> missing `mut` on `replacement`), then the final rerun passed. `crates/ui-gpui` was unchanged
> during the review. The command results below are the final passing runs.

## Bottom line

**No BLOCKER in the crash, storage-corruption or security sense.** The desktop starts, composes built-ins
and applications, survives a corrupt or locked database, offers a copy-only emoji mode, and passes its package
checks. There are **two HIGH** findings:

1. **The saved-quicklink path is not reachable by a user.** The desktop reads the
   `quicklink-library` SQLite record, but the only CLI authoring commands write a separate
   JSON `--library` file and never touch that record. `ansa doctor` still reports zero
   quicklinks after a successful CLI import. L11's "saved quicklinks appear" criterion is not
   met end-to-end, and the settings text implies CLI authoring feeds the desktop when it
   does not.
2. **Onboarding cannot be completed keyboard-only.** "Test launch", "Skip", and "Reset" are
   plain mouse-only `div` buttons; Enter on the TryLaunch step is deliberately blocked until a
   launch is verified or skipped. A keyboard-only user cannot get past TryLaunch, which is a
   functional F08 gap in a keyboard-first launcher.

**L11 is acceptable only as a deliberately narrower slice**: read-only quicklink composition
with an explicitly documented seeding mechanism, and onboarding declared mouse-only. For a
bounded first desktop slice that is a defensible scope; for ticket closure against its own
"saved quicklinks appear" and "documented manual checklist" criteria it is **not acceptable**.
The code is reviewable and the core daily-launcher path is sound; H1 and H2 need either fixes
or an explicit scope change.

## Requirement-by-requirement verification

### Data directory and startup

- **Precedence is correct.** `resolve_data_dir` (`daily.rs:34-44`) checks a non-empty
  `ANSA_DATA_DIR`, then `LOCALAPPDATA\Ansa\alpha` on Windows, then `.ansa-alpha`.
  `default_data_dir` is read once in `Launcher::new` (`lib.rs:203`) with no disk I/O.
- **Background open is correct.** `refresh_catalog` moves `driver` into
  `cx.background_executor().spawn(...)` (`lib.rs:775-804`). `DailyDriver::open`,
  `discover_applications` and `compose_catalog` all run there. No storage call is on the
  render path.
- **No startup block or panic found.** The window is created before refresh; the initial
  catalog is the four built-ins. `--smoke-test` exits 0. A corrupt `ansa.sqlite` leaves the
  process alive after 4 s; a second process on the same database also stays alive. No new
  user-input-reachable `unwrap`/`expect` was found: `daily.rs:76` is a static ID, and the only
  production `expect` in `lib.rs` (`:1765`) is guarded by `self.panel.is_some()`.
- **Storage failure keeps usable state.** On `DailyDriver::open` failure, `legacy_catalog`
  supplies built-ins + discovered apps (`daily.rs:259-270`); the status combines the summary
  with `storage_recovery` (`lib.rs:817-824`); `settings_detail` repeats the full recovery
  (`lib.rs:538-545`). Locked/corrupt/too-new errors come from the storage crate with the
  correct distinctions (`crates/storage/src/error.rs:84-95`, `:121-124`). The recovery text is
  truncated in the footer (L7), and `Start Setup` is unavailable while storage is failed,
  which is honest but means onboarding waits for recovery.
- **Quicklink load failure is not treated as a storage failure.** That is deliberate, but
  its warning is dropped (M3).

### Catalog composition and quicklinks

- **Composition itself is correct.** `compose_catalog` builds built-ins, apps including
  broken/packaged entries, then resolved quicklinks (`crates/alpha/src/catalog.rs:161-328`).
  Only enabled HTTP(S) targets with `Browser`/`DefaultApp` openers, no required arguments,
  no unresolved placeholders and a passing preview are emitted. Local/FileManager/
  unsupported/unresolved entries are skipped with reasons. The raw template is never used as
  a target; the emitted `url` is `preview.target()` (`catalog.rs:287-321`). Tests cover
  static web links, optional defaults, required arguments, local paths, unsafe schemes and
  placeholder integrity (`crates/alpha/tests/catalog_composition.rs`).
- **The desktop never verifies the raw template itself, but doesn't need to:** it only sees
  the resolved target, and `open_url` revalidates at launch.
- **Omitted-quicklink reporting is correct for a composed library.** `CatalogLoad.summary`
  reports the launchable count and skipped count (`daily.rs:181-201`);
  `skipped_warning` names the first three with `+N more` (`daily.rs:209-235`). The reasons
  are human-readable.
- **The saved-quicklink path is broken (H1).** The desktop reads the in-memory library loaded
  at `DailyDriver::open`. A normal refresh reuses that driver and never calls
  `reload_quicklinks` (`lib.rs:779-788`), so an externally added record requires a restart.
  More fundamentally, no CLI command writes the driver record: `ansa quicklink ...` uses a
  separate JSON `--library` (`apps/cli/src/main.rs:291-403`). The alpha `DailyDriver` exposes
  `import_quicklinks`/`commit_quicklink` (`daily_driver.rs:222-253`), but no UI or CLI calls
  them. The probe above demonstrates the resulting zero persisted/launchable count.
- **Refresh preserves the rest.** Query, selection by ID, emoji mode and setup state survive;
  `Engine::replace_catalog` deduplicates and preserves selection when the ID still exists
  (`crates/core/src/lib.rs:327-336`). The built-in IDs/titles change between pre-refresh and
  composed catalogs (L4), so a selected built-in can jump and "Integration Status" becomes
  "Settings".
- **Counts/warnings are mostly truthful.** The summary is derived from the actual
  composition; `1 applications` and the "local only" wording are cosmetic (L7). The corrupt
  library warning is not truthful (M3). A composition failure correctly falls back to
  legacy and adds a warning (“Quicklink composition failed…”), but if the library itself is
  unreadable there is no skipped list to report.

### Onboarding

- **Steps and mouse path exist.** Welcome → Shortcut → TryLaunch → Integrations → Done; the
  setup document shows title/status, step count, shortcut state, launch state, warnings,
  load warning and messages (`lib.rs:1259-1353`). Continue, Check, Test launch, Skip, Reset
  and Close are wired (`:584-764`). The model's transitions are persisted atomically by
  `JsonFileStore` (`crates/onboarding/src/store.rs`).
- **Shortcut probe.** On a fresh/unready Shortcut step, `setup_continue` calls
  `HotkeyProbe::new(self.hotkey.is_some(), reason)` (`lib.rs:585-618`), so the requested
  `self.hotkey.is_some()` source is used, and `select_shortcut` only records `Available`.
  **But** if `shortcut_ready()` is already true, no probe occurs (M2), so a persisted
  `Registered`/`UnverifiedDefault` can carry forward. The view is honest enough to display
  “this session: not registered”, but the flow can still complete.
- **Launch probe.** `CatalogLaunchProbe` calls the real `launch_or_switch`
  (`daily.rs:458-492`). `Launched`/`Switched` map to `OnboardingLaunchOutcome::Launched`;
  `Denied`/`Failed`/`NoTarget` map to `Failed`; `Unverified` stays `Unverified`.
  `Onboarding::try_launch` records only `is_launched()` (`model.rs:642-659`). No fabricated
  success path was found in the adapter or model. The UI's “Verified launch” wording overstates
  shell acceptance (L1), and `CatalogLaunchProbe` has no unit test (M5).
- **No-target case.** With no applications, Test launch explains and does not fabricate
  (`lib.rs:691-697`). With broken apps, failure is shown and not recorded. The setup screen
  does not preview the chosen target (L8).
- **Skip/reset.** Skip records warnings when the step had no prior result; Reset clears state
  without confirmation (L2/L10). Persistence is via `onboarding.json`; corrupt valid-UTF-8
  JSON is warned and fresh, invalid UTF-8 is silently fresh (L6).
- **Keyboard/focus.** Enter is globally bound; on TryLaunch it refuses until verified. Tab
  toggles the footer control only. There is no keybinding or focus path to Test launch, Skip,
  Reset, Check or Close. Escape closes setup with composition guard. This is H2.
- **IME.** The global `execute`/`navigate`/`copy_target` paths check `is_composing`; the new
  setup button handlers do not (M6). A mouse click during composition can launch, skip, or
  reset. Emoji row clicks have the same gap.

### Emoji mode

- **Parsing is explicit and bounded.** `emoji smile`, `emoji: smile`, and bare `emoji`
  (browse) are recognized; `emojis`, `smile emoji`, and `Emoji Party` are not
  (`daily.rs:285-303`, tests `:536-543`). Search is capped at 24 in the desktop
  (`EMOJI_LIMIT`, `daily.rs:28`, `:306-308`); the emoji crate also caps query length at 64
  and results at 50. Selection resets to index 0 on every query change; Up/Down/PageUp/PageDown
  clamp.
- **Grapheme and names.** The dataset validates one extended grapheme per base/variant,
  non-empty names, and distinct variant names (`crates/emoji/src/dataset.rs:361-408`). The
  UI displays the name and accessible name and uses the base grapheme for copying
  (`lib.rs:1659-1739`). No variant picker is exposed; that is a documented limitation, not a
  false claim.
- **Copy-only.** `copy_emoji` calls `cx.write_to_clipboard` with only the grapheme and sets a
  "paste manually" status (`lib.rs:523-535`). There is no insertion or paste call anywhere
  in `ui-gpui`. Clipboard write success is not verified (the API is fire-and-forget), so the
  status is a claim rather than an observation; manual clipboard verification is still needed.
- **No root/calculator/panel conflict.** Emoji mode is checked before calculator/execute in
  `execute_primary`; the query "emoji …" routes as Search; the action panel is blocked with a
  message; the calculator UI is suppressed. Up/Down operate on emoji results only. Escape
  dismisses the launcher, as at root.
- **IME conflict remains (M6).** Enter/Up/Down/Ctrl+Shift+C are guarded; mouse row clicks are
  not. The search itself runs on composition text changes, which is bounded and does not
  execute.
- **Accessibility.** Under `upstream-candidate`, the emoji list has `Role::List` with
  `"Emoji results"` and a set size, and each row has `Role::ListItem`, the accessible name,
  selected state and a logical position (`aria_position_in_set(index)`; AccessKit positions
  are zero-based and the Windows adapter adds one, per the comment at `lib.rs:1592-1594`).
  This is structurally good. There is no live announcement of the selected emoji when moving
  with arrows (`navigate`'s emoji branch, `lib.rs:259-268`); focus stays in the input. The
  copy status is announced only through the candidate-only live status. In the default build
  this role/label code is compiled out (M4).

### Accessibility / F08

**What exists:**

- The app retains the pre-existing candidate-only shell semantics: search input label,
  result list/item roles, selected state, logical position/set size, action menu roles, and
  a `Role::Status` + `Live::Polite` footer (`lib.rs:1089-1101`, `:1354-1358`,
  `:1587-1610`, `:1786-1790`; `live_status.rs`).
- New emoji results have candidate-only list/item roles, labels, selected and position
  (`lib.rs:1734-1760`); the emoji error is a candidate-only `Role::Alert`
  (`:1631-1636`).
- The setup document is a candidate-only `Role::Document` with a label
  (`lib.rs:1354-1358`).

**What does not exist:**

- **Setup buttons have no role, no explicit aria label, and no focus handle or keybinding**,
  even under the candidate feature (`lib.rs:96-115`). A screen reader may read the visible
  text but cannot invoke the control. This is also the H2 keyboard blocker.
- Setup messages, persisted warnings, load warnings and the skipped-quicklink banner are
  plain text with no `Alert`/live semantics. A screen-reader user may not hear
  “Cannot continue”, a shortcut failure, or a skipped-quicklink warning. (The footer status
  does have a candidate-only live region, but it does not carry these document messages.)
- Emoji Up/Down has no live announcement of the selected name; the visual highlight is the
  only cue.
- The default build uses pinned GPUI 0.2.2, which has no accessibility bridge

### Blocking I/O, unbounded work, panics, data loss

- **No blocking I/O on the render path.** Render calls `describe_onboarding` (in-memory),
  `route_query` (bounded, pre-existing), `skipped_warning` (first 3), and reads cached emoji
  results. Storage open/discovery/composition are background (`lib.rs:775-804`).
- **Interaction-path blocking is bounded but real (L5).** `open_setup` reads
  `onboarding.json`; every transition writes + fsyncs + renames it; Test launch enumerates
  windows and may poll 3×10 ms. These are explicit user actions, not render work.
- **Unbounded work:** emoji search is bounded (24/64/50), skipped warnings are capped at 3,
  catalog composition is bounded by the discovered catalog, and refresh coalesces to one
  active + one queued run (`crates/core/src/refresh.rs`). `JsonFileStore::load` reads the
  entire onboarding file with no size cap (local file, low risk). `Engine::results()` still
  ranks the catalog lazily on render, including in emoji mode where results are hidden; this
  is pre-existing and small at the current catalog size.
- **Panics/unwraps:** no new user-input-reachable panic found. The only production `expect`s
  are a static command ID (`daily.rs:76`) and the guarded panel (`lib.rs:1765`);
  `RefreshGate`'s ticket-exhaustion `expect` is practically unreachable. Tests' `unwrap`s are
  test-only.
- **Data loss:** no storage destructive behavior was found. Storage errors do not delete or
  migrate down; corrupt quicklink records are not overwritten; onboarding saves are atomic.
  The material risks are the unconfirmed Reset (L2), the silent fresh start on invalid UTF-8
  (L6), and the hidden corrupt-quicklink warning (M3). H1 means users may believe they have
  no quicklinks rather than that none can be added.
