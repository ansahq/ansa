## Implemented contract

### Frozen corpora

- `ansa-commands-10k-v1`: deterministic 10,000-command JSONL generator,
  2,720,202 bytes, SHA-256
  `c52ff8497f1052db3eed78cebd2d28ef5ae6bec75cbaa81960316d3df0256839`.
- `ansa-file-index-1m-v1`: deterministic synthetic file paths/titles with
  1,000,000 entries, 144,958,066 serialized bytes, SHA-256
  `82dd01f9fca14493c56fcd56d6be253cd66e1e0781dc424edb4f6933cab1fab4`.
  The million lines are generated, never committed.
- Each manifest records version, seed, count, line ending, bytes and hash. A
  test compares generated bytes with the manifest; changing generated bytes
  requires a version bump.

### Harness CLI

Profiles: `quick` (default), `full`, `soak`, `cancel-flood`,
`delayed-provider`, `corpus`. Unknown profiles/flags exit non-zero with usage.
Useful options: `--idle-seconds=N`, `--launch-samples=N`, `--query-rounds=N`,
`--frames=N` (1..=300), `--index-entries=N`, `--flood-iterations=N`,
`--desktop=PATH`, `--output-dir=PATH`.

Every run records build commit/dirty flag, rustc version, OS version/build,
CPU model, logical/physical cores, total RAM, active power scheme, corpus
version/hash, sample counts and UTC timestamp. Missing `git`, `rustc`,
`powercfg`, registry or metrics become explicit `unavailable`/`unknown`
values; runs do not fail for them.

Measurements always carry p50/p95/p99 and sample counts. No average-only
measurement exists. Output is appended to
`docs/benchmarks/runs/<timestamp>/raw.jsonl` with a `summary.md` that labels
every value `measurement` and states `budget: not defined`.

### Launcher fixture

`ansa-desktop.exe --perf-smoke-test` is compiled only under
`debug_assertions`. It creates the real launcher window, prints
`ANSA_PERF_FIRST_FRAME_US:<micros>` on the first presented frame, then runs
`--perf-frames=N` (default 60, capped at 300) no-op frame callbacks printing
`ANSA_PERF_FRAME:<index>:<micros>`, prints `ANSA_PERF_DONE`, and quits. It does
not register the summon hotkey, discover applications, launch external apps or
write the clipboard. Normal startup is unchanged when the flag is absent.
Because the marker is debug-only, launch samples use
`target/debug/ansa-desktop.exe` even when the harness is release.

### Resource measurements

- Working set / RSS-equivalent / private bytes from
  `GetProcessMemoryInfo` over `ansa-bench` plus direct children.
- PSS by `VirtualQueryEx` + `QueryWorkingSetEx` page aggregation. If it cannot
  be computed, reports print `pss=unavailable`; it is never invented.
- GPU allocation is not measurable here, so reports always print
  `gpu=unavailable`.
- Idle CPU uses `GetProcessTimes` sampled once per second; reports CPU seconds,
  percent of one core and the sample count. Default named
  indexer/clipboard/provider worker count is zero.
- Cancellation flood verifies stale revision/invocation tokens are rejected;
  a single acceptance is a hard failure. Throughput is measured per operation
  inside 100-rejection batches.
- Delayed provider sleeps in a local thread (no network), changes the
  query/invocation, then proves the late batch is rejected.

## Unresolved / unverified

- No latency budget exists, so no budget is met. The measured query numbers are
  in-process `Engine::set_query` + `results()` on a 10k corpus, not physical
  input, IME, paint or display latency.
- First-frame values are from a debug launcher fixture; internal time starts at
  `run_with_application`, while wall time includes process creation. OS loader
  time is excluded from the internal value.
- `cold_launch` means first spawn in the harness run, not after reboot or cache
  purge. No hardware-cold boot was measured.
- PSS is an estimate; GPU allocation is unavailable; idle CPU covers the
  harness process tree, not whole-machine power.
- 30-minute idle, 30 cold/warm launches, 72-hour soak and end-to-end external
  validation remain unrun. F09 must not be marked closed on this evidence.
