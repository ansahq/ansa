# Benchmarks and performance evidence

`ansa-bench` is the reproducible performance/resource harness for the Ansa
foundation slice. It is deliberately separate from unit tests and from the
older `ansa-core` `search_bench` example.

Every number emitted by this harness is labelled **measurement**. This
repository defines **no latency budget**, so every report also states
`budget: not defined`. No value here is a pass/fail threshold, and no value is
hardware-independent.

The generated 2.7 MB command corpus is not checked in; its deterministic
generator plus frozen manifest and hash live in
`fixtures/bench/corpus-v1.manifest.json`. The one-million-entry file-index

`fixtures/bench/file-index-v1.manifest.json`. Changing generated bytes requires
a version bump and a new hash.

Verify both hashes:

```powershell
cargo run --release --locked -p ansa-bench -- corpus
```

## Profiles

| profile | what it does | status in this checkout |
|---|---|---|
| `quick` | 3 launcher spawns (1 labelled cold, 2 warm), warm 10k query sweep, memory, 5 s idle CPU | run |
| `full` | 30 launcher spawns (1 labelled cold + 29 warm), 1M-entry synthetic index, 1800 s idle | **not run** |
| `soak` | 259200 s (72 h) idle/soak | **not run** |
| `cancel-flood` | stale/current `apply_batch` flood, 100-rejection batches, percentiles | run |
| `delayed-provider` | simulated sleeping provider, no network | run |
| `corpus` | manifest/hash verification only | run |

`full` and `soak` are not claimed. An overridden invocation is explicitly
marked `partial validation run (NOT the full profile)` in `summary.md`.
`full` requests 30 launcher spawns total: the first is labelled cold and the
remaining 29 warm.

The launcher first-frame marker is debug-only. `scripts/bench.ps1` therefore
builds release harness/desktop as required and also builds
`target/debug/ansa-desktop.exe`, passing it with `--desktop=...` for launch
samples. A release desktop ignores `--perf-smoke-test` and hangs in normal UI;
the harness reports the missing marker rather than inventing a frame time.

## Commands

Run the bounded profile directly:

```powershell
cargo run -p ansa-bench -- quick
```

Run release-mode with the debug-only launcher fixture:

```powershell
cargo build --release --locked -p ansa-bench -p ansa-desktop
cargo build --locked -p ansa-desktop
.\target\release\ansa-bench.exe quick --desktop=.\target\debug\ansa-desktop.exe
```

One command per profile (builds release and the debug launcher fixture):

```powershell
pwsh scripts/bench.ps1 quick
pwsh scripts/bench.ps1 full
pwsh scripts/bench.ps1 soak
pwsh scripts/bench.ps1 cancel-flood
pwsh scripts/bench.ps1 delayed-provider
pwsh scripts/bench.ps1 corpus
```

Useful overrides: `--idle-seconds=N`, `--launch-samples=N`,
`--query-rounds=N`, `--frames=N` (1..300), `--index-entries=N`,
`--flood-iterations=N`, `--output-dir=PATH`, `--desktop=PATH`.

Unknown profiles/flags exit non-zero with usage. The desktop fixture also
accepts `--perf-frames=N`; it creates the real launcher window, prints
`ANSA_PERF_FIRST_FRAME_US`, per-frame intervals and `ANSA_PERF_DONE`, then
quits. It never registers the summon hotkey, discovers applications, opens
external apps, or writes the clipboard.

## Output

Each run appends raw records to
`docs/benchmarks/runs/<timestamp>/raw.jsonl` and rewrites that run's
`summary.md`. Raw records carry profile, name, unit, samples, p50/p95/p99,
min/max, failures, machine identity, corpus identity and build identity.

## Limitations

- `Engine::set_query` + `results()` is in-process model timing; it is not
  end-to-end physical input, IME, paint, or display latency.
- First-frame timing uses a debug launcher fixture. The internal marker starts
  at `run_with_application`; wall time includes process creation. Loader time
  is excluded from the internal value.
- `cold_launch` is only the first spawn in the harness run; no reboot or
  filesystem cache purge was performed.
- PSS is a `QueryWorkingSetEx` estimate. GPU allocation is not measured.
- Idle CPU covers the `ansa-bench` process only; it is not whole-machine power.
- The 1M file index is a synthetic harness baseline, not the production
  indexer.
- No budget is defined, met, or claimed. F09 is not closed by these runs.

The older `cargo run --release -p ansa-core --example search_bench -- --jsonl`
trace remains a smaller synthetic ranking microbenchmark and is not
end-to-end evidence either.
