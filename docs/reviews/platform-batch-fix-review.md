# Independent platform-batch fix verification — ANS-82–99

**Do not merge.** The passphrase and retained-selection fixes hold. The X11 protected-offer and Linux opener fixes leave reachable races, and the macOS hotkey fix introduces a wrong FFI return type. This is a code verdict, not a native acceptance verdict.

## Prior findings

### HIGH

1. **RESOLVED — passphrase header binding.** `crates/vault/src/portable.rs:248–307,319–337` checks the exact session header before unwrapping or rewriting it. Unlock clears the cached key before validation; change also checks that the wrapper contains the cached key and updates the snapshot only after publication. The old-header fixture (`crates/vault/tests/portable.rs:305–345`) and both same-ID/different-key fixtures (`crates/vault/src/portable.rs:1037–1144`) passed on Windows. This is a between-operations guarantee under the documented single-writer assumption, not protection against a write racing an in-flight change.

2. **PARTIAL — X11 protected-offer race.** The grab serializes the owner query and conversion when the grab succeeds. But the final XFixes drain is **before** the grab, and the check under the grab compares only the owner window ID (`crates/clipboard/src/linux/x11.rs:109–137,164–189,365–378,429–465`). Repro with a fixture: screen unmarked `TARGETS`, then reassert the clipboard with the **same window** and a marked offer after the final drain but before the server processes the grab. The XID matches, the payload request goes out, and the queued XFixes event only discards the result afterward (`:510–528`). The fake server only changes the XID (`:822–829,860–886`). `grab_server()` also drops the void cookie without checking for a server error. Require a confirmed grab and check the queued selection generation under it before issuing the conversion.

3. **PARTIAL — Linux opener identity.** The exact original and canonical path/type/mode/stamp are rechecked after both MIME queries, and the folder is rechecked after its handler query (`crates/platform-api/src/opener.rs:186–268`, `crates/platform-api/src/linux_native.rs:141–164,211–237`). This rejects the original replacement during the default-handler query. But `open_target()` then waits for the shared child lock before `spawn()` (`linux_native.rs:342–345,563–587`); another open holds that lock during its 750 ms observation. With an inert slow opener occupying the lock, replace a second document after it revalidates but while it waits: the helper gets an unchecked object. Also, after a failed `ShowItems`, the fallback takes its **first** folder stamp (`:167–237`); a parent retargeted during that helper is adopted. Validate after the in-process wait and bind the fallback directory across helper calls. Even then a pathname handoff has a residual OS-level race. The new Linux-only test assertion is separately broken (R2).

4. **RESOLVED — retained Unix selections.** Each discovery issues a token; `Snapshot::get_selected` checks path, ID and token before either adapter's stamp recheck (`crates/platform-api/src/catalog.rs:18–29,226–249`, `linux_native.rs:48–78`, `mac_native.rs:45–54,90–98`). GPUI retains the rendered entries and uses this API for launch and setup (`crates/ui-gpui/src/lib.rs:592–600,663–684,962–980,1082–1117`). Host token/recheck fixtures passed. The legacy `launch_or_switch_identified(path, id)` still launches from the **current** snapshot by design; `crates/platform-api/src/lib.rs:406–427` explicitly says it cannot validate a retained selection. It is not a safe substitute for the new API.

### MEDIUM

1. **PARTIAL — X11 setup deadline.** Socket reads and writes now check the deadline directly, and a FIFO already present at the metadata check is skipped (`crates/clipboard/src/linux/x11.rs:48–86,222–256,599–621`). However, pinned `x11rb-protocol` 0.13.2 `src/xauth.rs:131–168,248–252` re-resolves and opens the path with blocking I/O and no read cap. A swap after the stat or a stalling regular-file filesystem can still hang under the session mutex; a file that grows after the stat is not capped at 64 KiB. The host/hotkey copy has the same stat/open gap and joins the worker even on initialization timeout (`crates/platform-api/src/host_lifecycle/x11_transport.rs:126–147`, `crates/platform-api/src/hotkey/x11.rs:89–118`). The new tests check the size predicate and expired ready socket, not the setup interleaving.

2. **UNRESOLVED — queued macOS press.** Commit is after save, a save error keeps the old route, and a non-secure pre-fence press latches `down` before filtering, so its release clears the latch (`crates/platform-api/src/hotkey.rs:346–367`, `hotkey/macos.rs:143–170`). But the native timestamps are not comparable (R1). Even in the synthetic tick model, a pre-commit press in the **same tick** is accepted; the tests explicitly require this. The 32-bit comparison orders nearby ticks across wrap, but only within half a cycle. A fence kept for the life of a registration would reject fresh ticks a half-cycle later; the 64-bit fallback is unreachable with the current native inputs (`hotkey.rs:228–238,277–285,714–760,802–837`).

3. **PARTIAL — native prompt consent.** macOS explicit unlock skips the lock precheck and permits an interactive item query; routine reads retain both the precheck and fail-without-UI option (`crates/vault/src/native_macos.rs:48–74,126–155`). If that interactive query fails while the Keychain remains locked, there is no lock-state recheck or external-unlock instruction; e.g. `errSecInteractionNotAllowed` maps to `AccessDenied`, not `Locked` (`:167–175`). On Linux a fresh routine `Vault::open` passes `allow_prompt=false` but still reaches `add` and `create_item` (`crates/vault/src/lib.rs:348–367`, `portable.rs:131–155`, `native_linux.rs:37–70`). A provider's `CreateItem` prompt still gets executed by `secret-service` 5.2.0 (`src/collection.rs:140–175`). An unlocked-collection fixture returning a prompt would still see `Prompt` without opt-in; no such test was added.

4. **RESOLVED — case-variant vault fixture.** `crates/vault/tests/portable.rs:551–627` probes case sensitivity and tests a single case-preserving entry or deliberate two-file ambiguity as appropriate. The single-entry assertions agree with `find_secret_file` returning the actual enumerated spelling (`crates/vault/src/lib.rs:638–644,855–895`). Unix-only test compiled, not run here.

5. **RESOLVED — insertion ordering.** The final target observation precedes sequence/ownership checks, and the paste boundary receives the expected sequence with a contract to check both target and clipboard before input (`crates/clipboard/src/insertion.rs:277–287,454–491`). The fake-host sequence and owner races during final observation passed with zero paste attempts (`:793`); the public fake also checks the sequence (`crates/clipboard/tests/public_api.rs:146–152`). No production injector or atomic OS paste guarantee is evidenced.

6. **PARTIAL — volatile quota.** The encoded-byte estimator matches current vault framing conservatively, selects unpinned victims and makes room before sealing (`crates/clipboard/src/store.rs:222–241,950–1034,1084–1144,1737–1764`, `crates/vault/src/lib.rs:976–1000`). The 128 KiB pressure test passes, including all-pinned refusal. It wraps a volatile vault in the persistent `open_with_backend` test constructor, not production `ClipboardStore::open` (`store.rs:674–717,2198–2276`). The estimator cannot see other vault entries; a failed new seal can now permanently evict valid history (R3).

7. **PARTIAL — macOS glass request.** Requested and effective state are separate; removing Reduce Transparency restores the preserved request on activation, and Off stays Off (`crates/ui-gpui/src/lib.rs:225–240,304–316,340–350,1323–1374`). But there is still no update when the setting changes while the launcher stays active. The pinned `objc2-app-kit` 0.3.2 exposes `NSWorkspaceAccessibilityDisplayOptionsDidChangeNotification` (`src/generated/NSAccessibility.rs:188–191`); the lack of a GPUI hook does not close the finding. The Windows unit test exercises state transitions, not event delivery.

### LOW

- **RESOLVED — argv0 dedup.** The Linux dedup key now contains the invoked path as well as the canonical target and remaining launch parameters (`crates/platform-api/src/linux_catalog.rs:103–124,207–225`). The Unix symlink fixture (`:888–925`) checks two rows with distinct invoked paths; compile-only here.

## Regressions introduced by the fixes

- **R1 — HIGH: macOS hotkey FFI ABI mismatch.** `crates/platform-api/src/hotkey/macos.rs:62–68,104–110,137–143` declares Carbon `GetEventTime` as returning `u32`. The [SDK's `CarbonEventsCore.h`](https://github.com/phracker/MacOSX-SDKs/blob/master/MacOSX11.3.sdk/System/Library/Frameworks/Carbon.framework/Versions/A/Frameworks/HIToolbox.framework/Versions/A/Headers/CarbonEventsCore.h#L994-L1020) declares `EventTime` (`double`, seconds since boot), returned in the floating-point register, not the integer register. `TickCount` is an approximate 60 Hz `UInt32` clock, not the same unit. This makes ordinary fresh and queued press decisions unreliable, including after initial registration. Repro on a Mac: register a free chord and compare a fresh press and one queued during a slow save against the commit time. The defect is confirmed from the ABI; the runtime repro was not run. Use `GetCurrentEventTime`/`GetEventTime` with the correct ABI and an explicit conservative equal-time policy.
- **R2 — MEDIUM, CI-blocking: the Linux document regression test will fail.** `crates/platform-api/src/linux_native.rs:612–651` replaces the approved document with a symlink to `no-extension` but expects `"changed after policy"`. `revalidate()` propagates `capture()`'s `safe_document` error (`crates/platform-api/src/opener.rs:221–223,261–269,346–353`): `"Local file is not an allowlisted document type; reveal the path instead"`. The assertion fails before checking `opened`. Repro on Linux: `cargo test -p ansa-platform-api --locked --offline imp::tests::document_replaced_during_handler_query_never_reaches_the_opener -- --exact`. This is a source-traced failure, not an executed Linux result; CI runs the test suite on Ubuntu (`.github/workflows/ci.yml:98–104,151–152`).
- **R3 — MEDIUM: a failed capture can lose older clipboard items.** `crates/clipboard/src/store.rs:975–1034` removes existing rows and deletes their sealed values before the new `seal`; its error branch cannot restore either. Repro using synthetic data through the public memory-only path: prefill the vault with unrelated entries leaving about 2 KiB of encoded space, open with `max_items=1`, capture short text, then capture 128 KiB. The small row is evicted, the larger seal returns `LimitExceeded`, and no row replaces it. The old ordering retained history on a failed seal. Test the failing path and commit eviction only with a successful replacement, or reserve capacity up front without destroying the victims.

## Merge verdict

**Do not merge on code grounds. Two of the four original HIGH findings are cleared (H1, H4); H2 and H3 are not.** Before merge, close those handoff races, correct the Carbon ABI and fence, fix the Linux regression test, and prevent failed volatile capture from deleting valid history. The Xauthority deadline, Linux prompt consent/macOS recovery, and live glass update remain partially addressed and must not be represented as fixed.

**Before native acceptance, separately:** build/link on the native toolchains, exercise real Carbon/AppKit, keyring, X11/Wayland and desktop handoffs, and collect the required physical accessibility and glass evidence against the exact shipped build with independent review. No such run was performed; native acceptance remains **0/8** and did not determine this merge verdict.
