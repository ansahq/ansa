# Final independent platform-batch review — ANS-82–99

**Verdict: do not merge this implementation slice as-is.** The findings below are code defects, not missing native evidence. I reviewed the worktree diff, new sources, validation records, and CI wiring. Reproductions below are proposed regression tests unless noted; I did not rerun the workspace suites.

## BLOCKER

None at this severity. The HIGH findings are merge blockers for this slice.

## HIGH

1. **A live passphrase vault can adopt a replaced header.** `crates/vault/src/portable.rs:248–262, 280–297, 308–330`. Ordinary operations require exact header bytes; passphrase unlock and change only check the public profile ID. Unlock installs whatever key the current wrapper authenticates, and change can overwrite a wrapper other than the one the handle opened. **Test:** save the old header, change the passphrase, lock the same handle, restore the old header, and try the old passphrase. It currently succeeds and permits new writes; the existing handle should reject the replacement and stay locked. Also test a same-ID wrapper for a different fixture key.
2. **A protected X11 offer can receive a payload request before it is screened.** `crates/clipboard/src/linux/x11.rs:295–311, 321–345`. The ownership check and `ConvertSelection(CURRENT_TIME)` are separate server operations. A new owner can take over after the check and receive the payload conversion based on the *old* owner's `TARGETS`. The XFixes check prevents retaining the raced snapshot, but it cannot undo the request. **Test:** switch from an unmarked fixture to a marked fixture between the last owner check and payload conversion; assert that the marked owner receives no text/file conversion request, not merely that history stays empty.
3. **The Linux document opener can hand off a replacement that policy never checked.** `crates/platform-api/src/opener.rs:77–107`, `crates/platform-api/src/linux_native.rs:116–120, 225–256`. Canonicalization and the type/mode checks run before two helper calls. After the MIME query, the same pathname can resolve to a different object, yet it is sent straight to `xdg-open`. **Test:** with inert helper fixtures, replace an approved `.txt` file with a symlink to a disallowed local target during the default-handler query. Assert rejection and no `xdg-open` invocation. Apply the same invariant to the containing-directory reveal fallback (`linux_native.rs:155–164`).
4. **The Unix launch API cannot distinguish old and new selections with the same path and ID.** `crates/platform-api/src/catalog.rs:186–209`, `crates/platform-api/src/linux_native.rs:47–69`, `crates/platform-api/src/mac_native.rs:45–53, 78–98`. Rediscovery discards the selected stamps. `launch_or_switch_identified` then revalidates the *new* entry if the replacement retained its path and stable ID. GPUI serializes its own refresh/launch and guards displayed generations; the public adapter contract has no equivalent selection token. **Test:** retain an entry, replace its executable or manifest at the same path and ID, rediscover, then launch the retained entry. The old selection should be rejected while the newly selected entry remains launchable.

## MEDIUM

1. **X11 clipboard setup can wait indefinitely before the socket deadline applies.** `crates/clipboard/src/linux/x11.rs:102–127`, `crates/clipboard/src/linux.rs:86–105`. The pinned `xauth::get_auth` opens and reads `XAUTHORITY` with blocking file I/O while the clipboard session mutex is held. The clipboard stream also checks time only in `poll`, although x11rb can drain repeated successful reads without polling (`linux/x11.rs:45–67`). **Test:** with a disposable local X server, supply an authority FIFO with no writer and assert bounded failure; separately test an always-readable transport. The host/hotkey transport already checks read deadlines but still has a separate authority stat/open and joins the worker on timeout (`crates/platform-api/src/host_lifecycle/x11_transport.rs:126–147`, `crates/platform-api/src/hotkey/x11.rs:89–118`).
2. **A press queued during a macOS rebind can be delivered after commit.** `crates/platform-api/src/hotkey.rs:286–294`, `crates/platform-api/src/hotkey/macos.rs:123–148, 234–269`. The gate checks when the Carbon callback runs, not when the native press occurred. The main thread can be busy saving while the candidate chord is already reserved; the queued event then runs with the gate enabled and the new registration ID. **Test:** press the candidate during a deliberately slow successful save, let the AppKit loop drain, and assert no summon until a fresh press. Repeat with a failed save and verify the old chord still works.
3. **Native keyring prompts do not follow the explicit-consent contract.** `crates/vault/src/native_linux.rs:37–63`, `crates/vault/src/native_macos.rs:40–55, 105–128`. On Linux, `secret-service`'s `create_item` automatically invokes a returned prompt, even though `Vault::open` did not opt in; an unlocked check is not a guarantee that `CreateItem` won't ask for authorization. On macOS, explicit prompting cannot unlock a locked default Keychain because the lock precheck returns before the interactive query. **Test:** use a D-Bus fixture that returns a prompt from `CreateItem` after reporting unlocked; assert routine open does not call `Prompt`. For Keychain, verify routine access stays silent and explicit unlock either attempts recovery or gives a clear system-unlock instruction.
4. **The case-variant vault test fails on a standard case-insensitive macOS volume.** `crates/vault/tests/portable.rs:507–519`, `.github/workflows/ci.yml:94–104, 151–152`. `#[cfg(unix)]` does not imply case sensitivity. On case-insensitive APFS, `Token.sealed` and `token.sealed` resolve to the same file; the test cannot create the two aliases it asserts exist. **Test:** run `cargo test -p ansa-vault --test portable ambiguous_case_variant_aliases_fail_closed` with a case-insensitive `TMPDIR`; select the fixture branch by actual filesystem behavior.
5. **Automatic insertion can use an outdated clipboard observation.** `crates/clipboard/src/insertion.rs:449–480`. The final target check runs *after* clipboard sequence and ownership checks. A new copy during `observe_target` leaves a valid destination but the wrong clipboard, and `send_paste` still runs. No production injection adapter is wired. **Test:** have the fake host change the sequence/owner during the final target observation; require zero paste attempts. The host's checked paste boundary should validate both the destination and the expected copy.
6. **Memory-only clipboard capture can stop instead of evicting.** `crates/clipboard/src/store.rs:873–945`, `crates/clipboard/src/model.rs:29–34`, `crates/vault/src/lib.rs:157–158, 970–983`. History budgets plaintext while the volatile vault budgets hex-encoded ciphertext; the new value is sealed before any candidate evictions. At default limits, 63 distinct 128 KiB snapshots fit but the 64th exceeds the vault budget with encoding overhead, even though history admits it. **Test:** use synthetic, non-sensitive snapshots to fill the default store and continue capturing. Require evictable rows to make room and keep pinned rows intact.
7. **macOS Reduce Transparency can leave the UI stale or forget the glass preference.** `crates/ui-gpui/src/lib.rs:219–228, 324–330`. The code resamples on activation or a user glass toggle, not on accessibility display-option changes while active. Applying the opaque fallback also overwrites `self.glass`, so clearing the OS setting does not restore a previously requested effect. **Test:** simulate a live settings change without a focus event, then clear it; verify `Unavailable` while enabled and `Requested` afterward unless the user chose Off.

## LOW

- **Linux deduplication can hide distinct argv-zero launchers.** `crates/platform-api/src/linux_catalog.rs:103–120, 199–208`. Launch preserves the invoked executable name, but dedup keys only on the canonical executable, remaining args, working directory and terminal flag. **Test:** two entries invoke differently named symlinks to one inert multicall fixture; both rows should survive if their behavior differs by the invoked name.
